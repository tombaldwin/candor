## 6. AFTER THE RELEASE — the `[P1e]` review, and two defects it turned up

Running the clause question past a Fable reviewer returned **NO-GO on my proposal**, and the reason
matters more than the verdict: **what I recommended was byte-for-byte the version that had already been
built, measured destroying a committed report, and reverted** — with the reasoning sitting at the arm
site in three engines, twelve lines above code I had read the same night. My "only where a report exists"
narrowing was already that version's predicate; a committed report satisfies it.

It also corrected three claims I had given as fact: java does not behave like the other three (a bare run
persists nothing; the umbrella injects a NAMED sink), deletion is barred by the fail-open-by-absence rule
rather than the user-file-destruction review, and the gate genuinely cannot defend itself — but because
the hazard is an **event** (a refusal occurring after the report was written), witnessed only by the
refusing run. No function of (report bytes, tree bytes) computes it, which is what forces a write.

**Two defects fixed as a result, neither about the default prefix:**

1. **The hand-back restored its own placeholder** (candor-rust, live at `--out`). Three ordinary steps:
   scan a two-member workspace, delete a member and let any refusal arm the orphan, then scan the
   remaining member successfully. The completed run handed *its own placeholder* back, and
   `gate --report` then refused at exit 2 for ever. That is the exact state the hand-back exists to
   prevent, reached by running it twice. A placeholder is now recorded as "no previous report" and
   removed rather than restored — sound for a placeholder, never for a report, and both directions are
   pinned.

2. **java's `--gate-json` FILE sink had no shutdown hook**, so 37 raw `System.exit(2)` paths kept the
   arming stub describing a crash. I set out to funnel the 37; the codebase had already ruled that shape
   out in `armGateJsonStream`'s comment — *"the rule is over the RUN, not over the sites anyone
   enumerated"* — and the stream sink had had the hook since ⟨0.28⟩ while the file sink never did.

**Twice tonight the codebase had already recorded the answer to something I was about to do the long
way, and both comments were within a dozen lines of code I had read.**

## 7. `[P1e]` — TWO CANDIDATES, COSTED

**A — commit-point ownership.** The default prefix becomes a named sink once argv is accepted with no
`--out` and the target resolves. Covers content-driven refusals (the causes correlated with a changed
tree); excludes the argv death that destroyed the committed report. **Prerequisite:** the armer says
"only files positively identified as §2 reports" and means ANY candor report — in a polyglot `.candor/` a
rust refusal would arm java's and swift's live reports. That must land first.

**B — a refusal marker**, `.candor/REFUSED` naming cause and target, checked by `gate --report`, cleared
by a completing run. Destroys nothing. **Findable from all three locator forms** — the open question when
this was filed — provided the marker CARRIES the prefix it belongs to, so a single-`.json` locator can
scan its directory and match. Wider coverage than A (a marker can be written as soon as the target is
known, which is earlier than A's commit point). Costs: a new reserved file kind in §2.2, `gate --report
<single-file>` must consult a sibling, and marker staleness produces false reds.

**My read: B dominates on safety and coverage; A is cheaper only if the armer's blast radius is already
acceptable. The deciding question is whether a new reserved file kind is acceptable.**
