**Corpus permanently extended** — `tokio` (large cargo workspace, 10 member reports: the ⟨0.31⟩ ordering
fix needs a multi-report workspace and ripgrep was previously the *only* tree with that shape),
`hyper`, `execa` (densest `Exec` surface — every other ts entry is Net- or pure-shaped), `swift-nio`.

**A check I did NOT add.** Split invariance on a real workspace (scan tokio whole vs each member alone)
holds — 179 functions across four members, zero differing. But I could not establish that it CAN fail:
if a whole-workspace scan does not chain members to each other, "whole" and "alone" are the same
computation and the oracle is tautological. Inconclusive, so it stays out. A check that cannot fail is
worse than no check, because it reads as coverage.

**New oracle [5]: chain monotonicity on a real dependency graph.** Chaining regex's seven member reports
into ripgrep grows 33 functions' effect sets and shrinks none. It carries its own non-vacuity signal
(`grew > 0`) and refuses a run where chaining changed nothing. Calibrated both ways.

## 4. THINGS I GOT WRONG, ON THE RECORD

- **I filed a finding that was false and retracted it.** "Every query verb exits 0 when it cannot find a
  report" — measured with `out=$(cmd | head -1); rc=$?`, where `$?` is **head's** status and always 0. Run
  directly, all four engines exit 2 correctly. The backlog already carried this exact rule from
  2026-08-08, about `echo` mangling JSON; same rule, applied to the exit code. Kept as a withdrawal.
- **`release-preflight` had never printed `OK` all cycle.** My check `[12]` wrote `⟨0.$MAXRUNG⟩`; bash
  reads `⟩` as part of the variable name, and `set -u` killed the script at the final check — after every
  other check had printed. A gate that dies one line before its conclusion is indistinguishable from one
  that concluded badly. I had "calibrated" it against a standalone re-implementation of its own logic.
- **A vacuous probe, twice.** My compile-time `!Send` check spawned a thread whose body was `let _ = run;`
  — which under edition-2021 precise capture doesn't use the value, so nothing crossed. And my determinism
  probe reported "holds" before I'd shown it could fail; the first calibration of it was *also* broken.
- **PART 59's row C was wrong** — it seeded ts and swift at their default prefix and rust at a named one,
  reporting a divergence that doesn't exist. Fixing it turned up a real question, filed as `[P1e]`.
